# Product

## Register

product

## Users

Developers and Agent users who author local workflow projects in YAML and TypeScript, inspect and edit the same workflows visually, and run them through one shared execution model.

## Product Purpose

Open Flow makes workflow source equally usable by humans and Agents. The Workbench keeps project files as the source of truth while making graph structure, configuration, execution, and diagnostics directly understandable and editable.

## Brand Personality

Restrained, precise, and technical. The product should feel dependable and direct without hiding implementation facts or demanding attention for its own interface.

## Anti-references

Do not resemble a generic SaaS dashboard, a playful no-code canvas that hides source semantics, or a provider administration console that invents deployment and authorization state inside the local editor.

## Design Principles

- Keep source and execution semantics visible.
- Prefer familiar tool interactions over novel presentation.
- Make validation and compatibility failures actionable.
- Preserve useful information density without visual noise.
- Distinguish local authoring state from external service and deployment state.

## Accessibility & Inclusion

Preserve the Workbench's current accessibility baseline, including keyboard-accessible controls, visible focus, light and dark themes, localized interface text, and semantic status feedback. New interactions must not regress those behaviors.
